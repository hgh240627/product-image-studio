# 全自动套图生成 - 提示词规则审查

生成日期：2026-06-02

本文档记录当前版本实际应执行的新提示词规则，便于人工核对。

## 1. 当前生成流程

1. 商品识别
   - 使用多模态提示词模型读取产品图。
   - 输出短 JSON 字段：产品身份、购买单位、材质/结构、部件功能、正确用法、交互契约、隐藏风险。
   - 用户可见内容保持短，不显示“买家收益”和“禁止误判”长段。

2. 用户人工确认
   - 用户可改产品名称、商品事实、购买单位、组件清单、PCS 数量、包装排列、正确使用/材质结构。
   - 后续提示词生成使用用户修改后的信息。

3. 一次性分类提示词生成
   - 所有已选图片分类一次性发送给提示词模型，只调用一次 API。
   - 不再按单张图并发调用提示词模型。
   - 如果这次调用失败、超时、返回 JSON 不完整或缺任意一条提示词，立即停止，并把失败原因告诉用户。
   - 绝不启用本地短提示词兜底。
   - 保留用户自主选择图片分类和数量；系统只增强所选分类的提示词质量，不做自动套图规划。
   - 每个分类提示词加入“视觉案例语法”质量层：准确主体、商业角色、构图、光线/镜头、材质证明、文字规则和分组禁止项。

4. 作图
   - 只有提示词模型完整返回全部提示词后，才开始调用作图 API。
   - 作图 API 并发数由用户设置，范围 1-10。

## 3. 产品形态输入规则

### 单品

用户重点填写：

- 产品名称
- 购买单位
- 商品事实/要求
- 正确使用/材质结构

提示词重点：

- 一个产品本体
- 真实使用关系
- 不暗示额外配件或多件装

### 组合装

用户重点填写：

- 组合装名称
- 购买单位
- 组件清单
- 组件差异/出镜要求
- 正确使用/材质结构

提示词重点：

- 每个组件都作为购买单位的一部分理解。
- 不同颜色、规格、配件必须保持真实差异。
- SKU 图必须完整、可数、产品一致。
- 场景/卖点/A+ 可以只突出部分组件，但不能让买家误解购买单位。

### 多PCS装

用户重点填写：

- 多PCS装名称
- 购买单位
- PCS 数量
- 包装/排列方式
- 正确使用/材质结构

提示词重点：

- 数量或数量感必须真实。
- 可用整包、透明袋、可数排列、堆叠、扇形展开表达整包价值。
- 不随机增减 PCS 数量。

## 4. 商品识别字段

关键字段：

- `product_summary_zh`
- `product_package_mode`
- `quantity_requirement`
- `unit_of_sale`
- `unit_of_use`
- `use_relationship`
- `detail_focus_areas`
- `detail_focus_areas_zh`
- `part_function_map`
- `part_function_map_zh`
- `correct_use_method`
- `correct_use_method_zh`
- `interaction_contract`
- `misjudgment_risks`
- `forbidden_use_errors`
- `final_prompt_en`
- `negative_prompt_en`
- `warnings`

`interaction_contract` 必须包含：

- `grip_area`
- `working_area`
- `target_object`
- `contact_rule`
- `product_state_after_use`
- `target_state_after_use`
- `forbidden_scene_errors`

用途：

- 防止作图模型把使用动作画错。
- 防止产品被插入目标物、折断、融合、反向使用。
- 防止把辅助部件当主功能部件。
- 防止“使用后状态”错误：目标物变化，产品本身保持完整。

## 5. 图种规则

通用质量增强层：

- 参考优秀提示词案例的组织方式，但不复制外部案例原文。
- 每张图必须明确：产品身份、分类角色、构图/镜头、光线/材质、物理关系、文字规则、禁止项。
- 风格只用于提升商业表现，不能覆盖产品真实结构、购买单位、正确使用关系。
- 最终提示词应进行自检：是否回答一个买家问题、是否符合所选分类、是否可作为电商缩略图阅读。
- 当前表单里的商品事实优先级最高；旧 `analysis`、提示词模型改写结果、creative brief 都只能作为补充，不能覆盖当前商品事实。
- 如果最终作图提示词出现当前商品事实不支持的外来机制词（例如其他商品的收纳袋、拉链、衣柜收纳等场景），必须停止或丢弃该 creative brief，不能继续提交作图。

### SKU图

- 展示准确完整的购买单位。
- 产品完全一致，数量可数。
- 组合装必须保留每个组件、颜色、规格、配件。
- 多PCS装必须保留真实数量或真实数量感。
- 禁止道具、手、人物、食物、宿主物、文字、图标、标注、信息图。
- 允许干净真实台面、自然/棚拍光、真实接触阴影、材质质感提升。
- 加入品牌产品摄影语法：目录级清晰度、整齐几何、真实阴影、材质触感、可数排列。

### 白底图

- 只对产品或完整购买单位做精修。
- 背景必须是纯白 `#FFFFFF`。
- 只改善材质质感、边缘、光线、清洁度、小缺陷和展示质量。
- 不重设计产品，不改数量，不增删部件。
- 禁止台面、场景、道具、手、文字、图标、渐变和装饰。
- 加入精修/抠图语法：纯白隔离、清晰轮廓、准确颜色、干净边缘、真实材质。

### 卖点图

允许主题：

- 痛点解决
- 材质质感
- 结构优势
- 正确功能
- 使用步骤
- 组合装价值
- 多PCS数量价值
- 更轻松/更整洁/更可控的结果

限制：

- 每张图只表达一个主题。
- 产品必须准确、完整、物理合理。
- 不能把产品画成损坏、插入目标物、与目标物融合、反向使用或用错工作部件。
- 可用一个短标题和一个小副句，禁止长文案、假数字、风险参数、认证、价格、折扣。
- 加入信息卡片语法：一个主证明画面、一个短标题区、一个辅助提示，避免多主题海报和密集图标。

### 场景图

- 必须带一个短标题，建议 2-5 个词。
- 展示真实使用环境、真实比例、真实接触关系。
- 必须遵守 `interaction_contract`。
- 产品不需要占满画面，但必须可识别。
- 禁止密集信息图、箭头堆叠、长段文字、错误使用动作、错误使用后状态。
- 加入场景叙事语法：真实环境、自然镜头距离、真实比例、成人手部/动作仅在能说明用法时出现。

### 高级A+

- 用作详情页模块。
- 细节标注图归入这里。
- 可做材质/结构细节、使用步骤、对比模块、套装概览、价值故事。
- 允许短标题、最多 3 个标签/图标/标注/放大点。
- 每个标注必须指向真实可见细节。
- 禁止虚构参数、认证、性能数值、随机拼贴、过多小面板、产品重设计、错误使用关系。
- 加入详情页模块语法：一个主视觉证明、一个计划好的文字区、最多三个有依据的图标/标注/放大点、清晰阅读路径。

## 6. 使用方式错误专项规则

每个使用场景都要区分：

- 手握哪里。
- 哪个工作部件接触目标物。
- 接触目标物的哪个位置。
- 目标物使用后如何变化。
- 产品使用后是否保持完整。
- 哪些部件不能承担主功能。

削皮/刨丝类工具示例：

- 手握木纹手柄。
- 削皮时长开槽刀口贴住果蔬表皮。
- 梳齿用于刨丝/划丝，不默认削土豆皮。
- 侧边缺口用于局部修整，不做长距离削皮。
- 金属头不能插入土豆/蔬菜内部。
- 产品使用后保持完整，变化的是果蔬表皮或条状结果。

## 7. 最终提示词长度规则

- 提示词不是越长越好。
- 最终提示词应短、准、结构清晰。
- 不输出内部 `Prompt profile` 前缀。
- 不重复写产品身份、产品保真、物理合理性同义段。
- 产品身份只写一次。
- 使用关系作为交互契约单独写。
- 避免长篇负面列表，用短分组约束。

## 8. AI工作台

新增独立子页面：

- 支持普通 AI 对话。
- 支持上传图片后问答。
- 支持文生图。
- 支持图生图/参考图修改。

AI 工作台不走套图流程：

- 不做商品识别强制步骤。
- 不做分类提示词规划。
- 不做 QA 审核。
- 直接调用当前配置的提示词模型或作图 API。
